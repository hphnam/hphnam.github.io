# Nam Hoang portfolio

Ready for GitHub Pages at https://hphnam.github.io.

## Publish with GitHub Desktop

1. Sign in as hphnam and create a public repository named exactly `hphnam.github.io` at https://github.com/new. Initialize it with a README. If that repository already exists, use it and review its existing contents before replacing anything.
2. In GitHub Desktop, clone that repository to your computer.
3. Extract this package. Copy its contents into the cloned repository: `index.html`, the complete `assets` folder, `.nojekyll`, and this README. Keep `index.html` directly at the repository root; do not put the enclosing extracted folder inside the repository. Preserve `.nojekyll` even if your file manager hides it.
4. In GitHub Desktop, commit with a message such as “Publish portfolio”, then click Push origin.
5. On GitHub, open the repository's Settings → Pages. Under Build and deployment select Deploy from a branch, choose `main` and `/(root)`, and Save.
6. When GitHub's Pages deployment succeeds, visit https://hphnam.github.io. Publishing can take up to 10 minutes.

## Publish through the browser instead

Create the same public repository. Extract this ZIP first; uploading the ZIP itself will not publish the website. Upload `index.html`, `.nojekyll`, and this README at the root, and upload the full `assets` folder with its folder structure preserved. GitHub's browser uploader accepts up to 100 files at once, so split the assets into batches if needed. Use GitHub Desktop if your browser cannot reliably preserve folder structure. Then configure Pages as in step 5 above.

## Updates

Replace changed files in the repository, commit, and push. GitHub Pages republishes from `main` automatically after setup.

This is the finished portfolio snapshot synced on 14 October 2026 from published version 43, including nine case studies, campaign media, client logos, the navy and red interface palette, and the interactive strengths DNA and bridge. Raw report downloads and source archives are excluded from this GitHub Pages copy. No build command, paid service, or server is required. Navigation uses hash routes, so the case-study links work with static hosting.

The original ChatGPT-hosted portfolio remains separate; future edits there must be copied into this repository to update the GitHub version.
